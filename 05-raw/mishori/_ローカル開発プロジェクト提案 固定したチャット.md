### 1. FFmpegでH.265（HEVC）とPCスペックについて

**結論：可能ですが、工夫が必要です。**

* **H.265変換:** FFmpegは標準で `libx265` というライブラリを使ってH.265エンコードが可能です。
* **スペック（メモリ12GB・グラボ無し）:**
    * **動作:** します。エラーで落ちることはほぼありません。
    * **速度:** ここが課題です。グラボ（GPU）がない場合、CPUだけで計算するため、H.265はH.264の数倍時間がかかります。例えば、10分の動画の変換に実時間以上（20〜30分など）かかる可能性があります。

**【解決策：Intel QSV】**
もしPCのCPUがIntel製（Core i5, i7など）であれば、**「Intel QSV（Quick Sync Video）」**という機能が内蔵されています。これは「CPU内蔵の動画処理回路」です。
FFmpegでこれを使うコマンド（`-c:v hevc_qsv`）を指定すれば、グラボ無しでも劇的に高速（爆速）にH.265変換ができます。これはぜひ試していただきたいポイントです。

---

### 2. オーディオスペクトラムの生成・合成フロー

**ご認識の通りです。**

FFmpegの中では、以下のようなフローで処理されます（これを1行のコマンドで書けます）。

1.  **音声入力:** 音声ファイル（mp3など）を読み込む。
2.  **波形生成:** `showwaves` や `showfreqs` というフィルタを使って、音声から「波形の映像」を動的に生成する。
3.  **合成（Overlay）:**
    * 背景画像（入力1）
    * 波形映像（入力2：生成されたもの）
    * これらを `overlay` フィルタで重ね合わせる。
4.  **出力:** 一本の動画ファイル（mp4）として書き出す。

「素材として一度書き出してから合成」もできますし、「メモリ上で生成してそのまま背景と合成して出力」も可能です。後者の方がHDD容量を圧迫せず、処理も一度で済みます。

### 3. OpenAI Whisper (Local版) のコストと範囲

**結論：完全無料です。**

* **費用:** 1円もかかりません。OpenAIのAPI（クラウド経由）は従量課金ですが、Local版はGitHubで公開されているオープンソース（MITライセンス）のモデルを自分のPCにダウンロードして使うため、**通信費以外は無料**です。
* **商用利用:** MITライセンスなので、商用利用（組み込んで販売など）も可能です。

**【スペックの懸念点】**
Whisperにはモデルサイズ（精度）が数段階あります。
* `tiny` / `base` / `small` / `medium` / `large`
グラボ無し・メモリ12GBの場合、**`base` か `small` モデル** が現実的な選択肢です。
* `large`（最高精度）は、CPUだけだと処理が重すぎて、実用的な速度が出ない（音声の長さの数倍時間がかかる）可能性があります。
* **対策:** Pythonライブラリの `faster-whisper` を使うと、通常のWhisperより数倍速く、メモリ消費も少ないため、CPU環境でも快適に動く可能性が高いです。

### 1\. なぜ「60倍」に引き伸ばしても音が壊れないのか？

FFmpegの標準機能（`atempo`フィルタ）で60倍に引き伸ばすと、声は「ガガガガ…」というロボットのような金属音になってしまいます。これは、音の波形を無理やり引き伸ばしてスカスカになるからです。

私たちが目指すのは、\*\*「Paulstretch（ポールストレッチ）」\*\*というアルゴリズムに近い処理です。

  * **仕組み:**
    1.  元の音声を、例えば「0.1秒」ずつの小さな断片（グレイン）に切り刻みます。
    2.  それぞれの断片を、少しずつ位置をずらしながら、\*\*何層にも重ね合わせ（オーバーラップ）\*\*ます。
    3.  さらに、断片の位相（波のタイミング）をランダムに散らします。
    4.  これを再結合すると、元の音の「響き（倍音）」だけが残り、滑らかで幻想的な「ドローン音（持続音）」になります。

#### Pythonコード (`eternal_stretch.py`)

このコードを保存し、同じフォルダに変換したい音声ファイル（`input.wav`）を置いて実行してください。
※ `input.wav` は、スマホで録音した3〜5秒程度の短い声や音がおすすめです。

```python
import numpy as np
import soundfile as sf
import sys

def load_audio(filename):
    """音声ファイルを読み込み、モノラル・正規化して返す"""
    data, samplerate = sf.read(filename)
    # ステレオならモノラルに変換（左右平均）
    if len(data.shape) > 1:
        data = np.mean(data, axis=1)
    # 正規化（音量を-1.0〜1.0に収める）
    data = data / np.max(np.abs(data))
    return data, samplerate

def paulstretch(audio, stretch_factor, window_size_seconds=0.25, samplerate=44100):
    """
    Paulstretchアルゴリズムの簡易実装
    audio: 入力波形データ
    stretch_factor: 引き伸ばす倍率（例：20.0なら20倍の長さになる）
    window_size_seconds: 音を切り刻む「窓」の大きさ（秒）
    """
    # 窓のサイズをサンプル数に変換
    window_size = int(window_size_seconds * samplerate)
    # 最適な窓サイズにする（計算効率のため2の乗数に近い偶数にする等の調整は省略し、単純に偶数化）
    if window_size % 2 != 0: window_size += 1
    
    # ハニング窓を作成（音の継ぎ目を滑らかにするための曲線）
    # 
    window = np.hanning(window_size)

    # ステップサイズ（どれくらいずらしながら配置するか）
    # 元の音声でのステップ幅
    step = int(window_size / 2) 
    
    # 必要な出力サイズを計算
    output_length = int(len(audio) * stretch_factor)
    output = np.zeros(output_length)

    # --- ここからが錬金術（Signal Processing） ---
    
    # 1. 元の音声の現在位置
    input_pos = 0
    # 2. 出力音声の現在位置
    output_pos = 0

    print(f"Processing... Stretch Factor: {stretch_factor}x")
    
    while input_pos < len(audio) - window_size and output_pos < output_length - window_size:
        # A. 元の音声から「窓」の分だけ切り出す
        chunk = audio[input_pos : input_pos + window_size]
        
        # B. 窓関数を掛ける（端っこをゼロにして滑らかに）
        chunk = chunk * window

        # C. FFT（高速フーリエ変換）： 時間領域 -> 周波数領域へ
        # これで音が「波の成分（スペクトル）」に分解されます
        spectrum = np.fft.rfft(chunk)

        # D. 位相（Phase）をランダム化する
        # ここが最重要！位相をバラバラにすることで「元のリズム」を破壊し、
        # 「スムーズなドローン音」に変えます。
        random_phase = np.exp(1j * np.random.uniform(0, 2*np.pi, len(spectrum)))
        spectrum = spectrum * random_phase

        # E. 逆FFT： 周波数領域 -> 時間領域へ戻す
        processed_chunk = np.fft.irfft(spectrum)

        # F. 窓関数をもう一度掛ける
        processed_chunk = processed_chunk * window

        # G. 出力配列に足し合わせる（オーバーラップ加算）
        output[output_pos : output_pos + window_size] += processed_chunk

        # 次の位置へ移動
        # 入力側は「少しだけ」進む
        input_pos += int(step / stretch_factor) 
        # 出力側は「窓の半分」進む
        output_pos += step

        # 進捗表示（簡易）
        if output_pos % (samplerate * 10) < step:
             sys.stdout.write(".")
             sys.stdout.flush()

    print("\nDone!")
    
    # 音量調整（クリッピング防止）
    max_val = np.max(np.abs(output))
    if max_val > 0:
        output = output / max_val * 0.8 # 少し余裕を持たせて0.8倍
        
    return output

# --- メイン処理 ---
if __name__ == "__main__":
    input_file = "input.wav"  # 用意した音声ファイル名
    output_file = "output_ambient.wav"
    factor = 20.0  # 何倍に伸ばすか（最初は20倍くらいがおすすめ）

    try:
        # 音声読み込み
        print(f"Loading {input_file}...")
        audio, sr = load_audio(input_file)

        # 変換処理
        ambient = paulstretch(audio, stretch_factor=factor, samplerate=sr)

        # 保存
        print(f"Saving to {output_file}...")
        sf.write(output_file, ambient, sr)
        print("Success! 再生してみてください。")

    except Exception as e:
        print(f"Error: {e}")
        print("※ input.wav が同じフォルダにあるか確認してください。")
```

#### このコードで何が起きているか（技術解説）

1.  **FFT（高速フーリエ変換）:** 音を「ドレミ」や「リズム」ではなく、「周波数の集合体」に分解します。
2.  **位相のランダム化 (`random_phase`):** ここがキモです。音の成分はそのままに、**「いつ鳴るか」というタイミング情報（位相）をあえてグチャグチャにします**。
      * これにより、アタック音（ピアノの打鍵音や、声の「パッ」という破裂音）が消え、ふわっとした音に変わります。
3.  **オーバーラップ:** ずらしながら重ね合わせることで、途切れのない無限の持続音を作っています。

### 3\. 具体的なFFmpegコマンド（最適解）

以下の条件でコマンドを組みました。これで1時間の動画でも軽快に動作するはずです。

  * **入力:** `input.wav`
  * **出力:** `output_spectrum.mp4`（背景は黒、波形は白）
  * **解像度:** 1280x720（HD画質で十分。4Kは無駄です）
  * **フレームレート:** 30fps（60fpsは容量の無駄です）
  * **コーデック:** H.264（互換性と圧縮率重視）

<!-- end list -->

```bash
ffmpeg -i input.wav -filter_complex "[0:a]showwaves=s=1280x720:mode=line:rate=30:colors=white[v]" -map "[v]" -map 0:a -c:v libx264 -preset fast -crf 23 -c:a copy output_spectrum.mp4
```

**コマンドの解説と調整ポイント:**

1.  **`showwaves`**: 一般的な波形生成フィルタです。
      * `mode=line`: 線で描画します（容量が軽い）。`p2p`（点）なども選べます。
      * もし周波数スペクトル（バーが上下するやつ）が良い場合は、`showwaves` の部分を `showfreqs=s=1280x720:mode=bar:colors=white` に変えてください。
2.  **`colors=white`**: 波形を白にします。**背景は自動的に黒**になります。編集ソフトで「スクリーン」合成すると、黒が消えて白だけ残ります。
3.  **`-c:v libx264`**: 一般的な圧縮形式です。
4.  **`-preset fast`**: エンコード速度を上げます。画質への影響は軽微です。もっと速くしたい場合は `veryfast` にしてください。
5.  **`-crf 23`**: 画質と容量のバランス設定です。
      * **さらに容量を減らしたい場合:** 値を `28` や `30` に上げてください。波形のような単純な図形なら、30くらいでも劣化は目立ちません。

### 4\. まとめ：加藤さんへの推奨設定

  * **戦略:** 「背景透過」で書き出すのではなく、「黒背景」で書き出してDaVinci Resolveで合成する。
  * **設定:**
      * 解像度: 1280x720（または640x360でも素材としては十分かも）
      * フレームレート: 20fps〜24fps（動きが激しくないのでこれで十分容量削減になります）
      * CRF値: 28（画質を落として容量削減）

**極限まで軽くするコマンド例:**
（これで1時間の動画でも100MB〜300MB程度になるかもしれません）

```bash

```

※ `-an` は「音声を含まない」オプションです。合成素材として映像だけ欲しい場合、音声データ分の容量（1時間で数百MB）も節約できます。編集ソフト上で元のwavと合わせればズレません。

# 仕様書：オーディオスペクトラム動画生成モジュール（高効率版）

## 1\. 概要

本モジュールは、アンビエント動画生成プロジェクト『Project Eternal』の一環として、音声ファイル（WAV等）から視覚的な波形動画（MP4）を生成するものである。
生成された動画は、動画編集ソフト（DaVinci Resolve）にて\*\*「合成用素材」\*\*として使用することを前提とし、徹底的な軽量化と高速化を図る。

## 2\. 設計思想と採用理由（Technical Rationale）

なぜ「背景透過（アルファチャンネル）」ではなく、「黒背景（Black Background）」を採用するのか、その技術的根拠を以下に示す。

### 2.1. 容量とコーデックの課題

  * **背景透過の場合:**
      * 背景を透明にするには、アルファチャンネルを持てる特殊なコーデック（ProRes 4444 や WebM/VP9）が必要となる。
      * これらはデータ量が膨大（1時間で数十GB〜100GB）になるか、圧縮処理が重く生成に実時間の数倍を要する。
  * **黒背景の場合（採用）:**
      * 世界標準の圧縮規格 **H.264 (MP4)** が使用可能。
      * H.264は「黒い単色」の圧縮効率が極めて高く、容量を\*\*数百分の一（数百MB）\*\*に抑えられる。
      * エンコード速度も高速で、Ryzenプロセッサの処理能力で十分に対応可能。

### 2.2. 合成モード「スクリーン」の数学的特性

DaVinci Resolve等の編集ソフトにおける「スクリーン（Screen）」または「加算（Add）」モードは、以下の計算を行う。

  * **計算式:** `結果色 = 背景色 + (素材色 × (1 - 背景色))` ※概念式
  * **特性:** **「黒（RGB: 0,0,0）」は数値が0であるため、計算結果に影響を与えず、完全に透明として扱われる。**
  * **結論:** 視覚的な結果は「背景透過」と全く同じでありながら、ファイル容量とＰＣ負荷だけを劇的に削減できる。

## 5\. 実装詳細（FFmpegコマンド）

以下のコマンドをPythonスクリプトから呼び出す、またはバッチファイルとして実行する。

### 5.1. 推奨コマンドライン

```bash
ffmpeg -i "input.wav" ^
-filter_complex "showwaves=s=1280x720:mode=line:rate=24:colors=white" ^
-c:v libx264 -preset veryfast -crf 28 ^
-an "output_spectrum.mp4"
```

### 5.2. パラメータ詳細解説

1.  **`-filter_complex "showwaves=..."`**
      * `s=1280x720`: 解像度。フルHD(1080p)が必要な場合は `1920x1080` に変更可だが、720pの方が生成が速い。
      * `mode=line`: 線画モード。容量が最も軽い。
      * `rate=24`: 1秒間の描画回数。アンビエント映像なら24fpsで十分滑らか。
      * `colors=white`: 波形を白にする。**重要**。
2.  **`-c:v libx264`**
      * 汎用性の高いH.264コーデックを使用。
3.  **`-preset veryfast`**
      * 圧縮効率よりも「生成速度」を優先する設定。画質への影響は軽微。
4.  **`-crf 28`**
      * 画質レベル（0〜51）。数値が大きいほど低画質・低容量。
      * 単純な白線のため、28程度まで上げてもブロックノイズは目立たず、容量を極限まで削れる。
5.  **`-an` (Audio None)**
      * **最重要最適化ポイント。**
      * 出力動画から「音声トラック」を削除する。
      * **理由:** 元の `.wav` はDaVinci Resolve上で別途配置するため、素材動画に音声が入っていると容量（1時間で約600MB）が無駄になるため。

## 6\. 運用ワークフロー (DaVinci Resolve)

生成された `output_spectrum.mp4` を使用した編集手順。

1.  **タイムライン配置**
      * **V1トラック:** 背景画像/動画（AI生成した画像など）
      * **V2トラック:** `output_spectrum.mp4`
      * **A1トラック:** 元の `input.wav`
2.  **合成設定**
      * V2トラックのクリップを選択し、「インスペクタ」を開く。
      * 「合成モード (Composite Mode)」を **「スクリーン (Screen)」** または **「加算 (Add)」** に変更。
      * → **黒背景が抜け、波形だけが表示される。**
3.  **色変え（オプション）**
      * 白で生成しておけば、Resolve上で「カラー」タブを使い、好きな色（ネオンブルーやピンクなど）に自由に着色可能。
