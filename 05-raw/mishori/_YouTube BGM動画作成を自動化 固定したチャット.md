## 1. 実現するための仕組み

この自動化には、音声処理に特化した**「pydub」**というライブラリを使用するのが最も効率的です。

1. **フォルダ内のWAVファイルを読み込む**: 特定のフォルダに入れたファイルを順番にスキャンします。
2. **時間の計算と結合**: 各ファイルの長さ（ミリ秒単位）を取得し、前の曲までの合計時間に足していくことで、正確な開始時間を算出します。
3. **テキスト出力**: 「00:00 曲名」の形式でリストを生成し、メモ帳（.txt）として保存します。
4. **音声出力**: すべてを繋ぎ合わせた1つのWAVファイルを書き出します。

-----

## 2. 自動化プログラムのサンプル（Python）

以下のコードは、指定したフォルダ内のWAVファイルを結合し、YouTubeの概要欄にそのまま貼り付けられるタイムスタンプを出力する雛形です。

```python
import os
from pydub import AudioSegment

def generate_youtube_bgm(folder_path, output_name):
    combined = AudioSegment.empty()
    current_ms = 0
    timestamp_list = []

    # フォルダ内のWAVファイルを取得（ファイル名順）
    files = sorted([f for f in os.listdir(folder_path) if f.endswith('.wav')])

    for file in files:
        # 1. タイムスタンプの作成 (HH:MM:SS 形式)
        seconds = (current_ms // 1000) % 60
        minutes = (current_ms // (1000 * 60)) % 60
        hours = (current_ms // (1000 * 60 * 60))
        
        time_str = f"{hours:02d}:{minutes:02d}:{seconds:02d}" if hours > 0 else f"{minutes:02d}:{seconds:02d}"
        song_title = os.path.splitext(file)[0] # ファイル名から拡張子を除く
        timestamp_list.append(f"{time_str} {song_title}")

        # 2. 音声の結合
        audio = AudioSegment.from_wav(os.path.join(folder_path, file))
        combined += audio
        
        # 次の曲の開始時間を更新
        current_ms += len(audio)

    # 3. ファイルの書き出し
    combined.export(f"{output_name}.wav", format="wav")
    
    # 4. タイムスタンプの保存
    with open(f"{output_name}_timestamps.txt", "w", encoding="utf-8") as f:
        f.write("\n".join(timestamp_list))

    print("処理が完了しました！")

# 使い方
# generate_youtube_bgm("音楽が入っているフォルダパス", "完成ファイル名")
```

# gemini response

BGM動画において、曲ごとの音量を整える「ノーマライズ」は、視聴者の快適さを左右する非常に重要な工程です。結論から言うと、**正しく行えば音質低下の心配はほぼありませんが、やりすぎると「曲の雰囲気」が壊れる**可能性があります。

YouTube運営の視点で、詳しく解説します。

---

## 1. 音量均一化（ノーマライズ）のメリット・デメリット

「ノーマライズ」には大きく分けて、最大音量を合わせる**ピークノーマライズ**と、人間の耳に聞こえる平均的な音量を合わせる**ラウドネスノーマライズ**があります。

| 項目 | メリット | デメリット |
| :--- | :--- | :--- |
| **視聴体験** | 曲が変わるたびに視聴者がボリュームを調整する手間（ストレス）がなくなる。 | 意図的に「静かに聴かせたい曲」まで音が大きくなり、情緒が損なわれることがある。 |
| **信頼性** | 「しっかり編集されているチャンネル」というプロっぽい印象を与えられる。 | 元々ノイズが多い音源の場合、音量を上げると同時に**サーッというノイズも目立つ**ようになる。 |
| **YouTube対策** | YouTube側の自動音量調整（ラウドネス等化）による急激な音圧下げを防げる。 | 処理設定をミスすると、音が割れる（クリッピング）リスクがある。 |

---

## 2. 視聴者の違和感と音質低下について

ここが一番気になるポイントかと思いますが、現代のデジタル処理において**「音質が目に見えて悪くなる」ことは稀**です。ただし、以下の2点には注意が必要です。

### ① 「ダイナミクス」の消失（違和感の正体）
音量を一定にするために「コンプレッサー」という機能を強くかけすぎると、曲の抑揚（サビの盛り上がりなど）が平坦になります。視聴者は「なんだか平べったい音だな」「ずっとうるさく感じる」という違和感を抱くことがあります。
> **対策**: 「音量を無理やり引き上げる」のではなく、「一番大きい音を基準に、全体のバランスを整える」程度に留めるのがコツです。

### ② YouTube側の自動機能との競合
YouTubeには**「ラウドネス・ノーマライゼーション」**という機能が備わっており、規定（-14 LUFS前後）より音が大きすぎる動画は、YouTube側で強制的に音量を下げられます。
* 自分で音量を上げすぎてアップロードすると、YouTube側に「音を小さくしろ」と処理され、結果的に迫力のない音になることがあります。

# YouTube用BGM制作支援ツール 要件定義書 (Ver. 1.1)

## 1. プロジェクト概要
YouTube用BGM動画（1〜2時間程度）の制作において、複数の音声資産を統合し、視聴適正の高い音量調整および目次情報を自動生成するコマンドラインツールの開発。

## 2. 実行環境・制約
* **OS**: Windows 10 / 11
* **ハードウェア**:
    * メモリ: 12GB（長時間ファイルのバッファリングおよびエンコード処理を考慮したメモリ管理を行うこと）
    * GPU: 非搭載（映像処理が発生する場合もCPUエンコードを前提とする）
* **外部依存**: FFMPEG (環境変数PATH設定済み)
* **開発言語**: Python 3.10以上推奨

## 3. 機能要件

### 3.1 音声ファイル一括入力・ソート
* 指定フォルダ内のWAVファイル（.wav）を全取得。
* ファイル名に基づき昇順で結合順序を確定。

### 3.2 高精度ラウドネスノーマライズ（音量均一化）
* **方式**: 単純なピークノーマライズではなく、**EBU R128規格**に基づいたラウドネス調整を採用。
* **ターゲット**: YouTubeの推奨基準に合わせ、統合後のラウドネス値を **-14 LUFS**（±1dB以内）に調整。
* **品質保持**: トゥルーピークが -1.0 dBTP を超えないようリミッター処理を行い、音割れ（クリッピング）を防止しつつ、曲ごとの聴感上の音量を一定にする。

### 3.3 非破壊的音声結合
* 各曲を無音・クロスフェードなし（デフォルト）で連結。
* **出力形式**: WAV (44.1kHz / 16-bit 以上を維持)。
* **ストリーム処理**: 2時間を超える出力でもメモリパンクを起こさないよう、ファイルを逐次読み込み・書き出しする実装。

### 3.4 YouTubeチャプター用タイムスタンプ生成
* 各曲の累計再生時間を計算し、以下のフォーマットでテキスト出力。
* **書式**: `[開始時間] [曲名]`
    * 1時間を超える場合は `HH:MM:SS`、1時間未満は `MM:SS` 形式。
    * 例: `00:00 曲タイトルA`
    * 例: `45:12 曲タイトルB`
    * 例: `01:02:05 曲タイトルC`

---

## 4. 詳細仕様

### 4.1 入出力インターフェース
* 実行時に以下の引数を受け取ること。
    1. `input_dir`: 素材WAVが格納されたフォルダパス
    2. `output_name`: 出力ファイル名（音声およびテキストの共通名）

### 4.2 処理フロー
1. 入力フォルダのバリデーション（WAVの有無確認）。
2. 各ファイルの長さおよびラウドネス値の解析。
3. 全ファイルを連結し、一括でラウドネス補正を適用。
4. 結合済み音声ファイル（.wav）の書き出し。
5. 累積時間に基づくタイムスタンプ（.txt）の書き出し。

* **拡張性**: 将来的なMP3出力や、静止画を合成して動画化（MP4）する機能の追加を容易にするためのモジュール化。
