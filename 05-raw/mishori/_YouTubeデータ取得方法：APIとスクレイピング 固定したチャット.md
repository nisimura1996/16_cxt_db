# gemini response

はい、**Google Colaboratoryを使用してYouTube動画のタイトル、ID、コメント、リンクを取得することは可能です。**

主に2つのアプローチがあります。

1.  **【推奨】YouTube Data API v3を使用する方法**（公式、安定的、高速）
2.  **【代替】スクレイピングツールを使用する方法**（APIキー不要、設定が簡単）

Colabですぐに動かせるコード例と共に、それぞれ解説します。

### 方法1：YouTube Data API v3 を使用する（推奨）

Google公式のAPIを使用する方法です。最も確実で、大量のデータ処理に向いています。

**事前準備:**

  * Google Cloud Consoleでプロジェクトを作成し、**YouTube Data API v3**を有効化する。
  * **APIキー**を取得しておく。

**手順:**
以下のコードをColabのセルに貼り付け、`YOUR_API_KEY` の部分をご自身のキーに書き換えて実行してください。

```python
# 1. ライブラリのインストール
!pip install google-api-python-client pandas

# 2. データの取得コード
from googleapiclient.discovery import build
import pandas as pd

# ★ここにAPIキーを入力してください
API_KEY = 'YOUR_API_KEY'
VIDEO_ID = '7-7knsP2n5w' # 例: Googleの動画ID (URLの v= の後ろ)

def get_video_info_and_comments(api_key, video_id):
    youtube = build('youtube', 'v3', developerKey=api_key)

    # --- A. 動画情報の取得 (タイトル, ID) ---
    video_response = youtube.videos().list(
        part='snippet',
        id=video_id
    ).execute()

    if not video_response['items']:
        return "Video not found"

    video_title = video_response['items'][0]['snippet']['title']
    video_url = f"https://www.youtube.com/watch?v={video_id}"

    print(f"タイトル: {video_title}")
    print(f"URL: {video_url}")
    print("-" * 30)

    # --- B. コメントの取得 ---
    comments_data = []
    
    # コメントを取得 (ページネーション対応)
    request = youtube.commentThreads().list(
        part='snippet',
        videoId=video_id,
        maxResults=20, # 取得数 (最大100)
        textFormat='plainText'
    )

    while request and len(comments_data) < 20: # テスト用に20件で制限
        response = request.execute()

        for item in response['items']:
            comment = item['snippet']['topLevelComment']['snippet']
            comments_data.append({
                'Author': comment['authorDisplayName'],
                'Comment': comment['textDisplay'],
                'LikeCount': comment['likeCount']
            })

        # 次のページがある場合はリクエストを更新
        request = youtube.commentThreads().list_next(request, response)

    return pd.DataFrame(comments_data)

# 実行
df = get_video_info_and_comments(API_KEY, VIDEO_ID)
df.head() # 結果の表示
```

**メリット:** 規約に準拠しており、動作が高速・安定している。
**デメリット:** 1日のリクエスト数に制限（クォータ）がある。

### 方法2：スクレイピングライブラリを使用する（APIキー不要）

「ブラウジング」に近い形ですが、Colab上でSelenium（ブラウザ操作）を構築するのは設定が複雑で壊れやすいため、**`youtube-comment-downloader`** という専用のスクレイピングライブラリを使うのが最も効率的です。

これはブラウザの挙動を模倣してデータを取得します。

**手順:**
以下のコードをColabに貼り付けて実行するだけです（APIキーは不要）。

```python
# 1. ライブラリのインストール
!pip install youtube-comment-downloader

# 2. データの取得コード
from youtube_comment_downloader import YoutubeCommentDownloader
from itertools import islice
import pandas as pd

# 取得したい動画のURL
YOUTUBE_URL = 'https://www.youtube.com/watch?v=7-7knsP2n5w'

def scrape_youtube_data(url):
    downloader = YoutubeCommentDownloader()
    
    # --- コメントの取得 ---
    # get_comments はジェネレータを返すので、必要な数だけ取得します
    comments = downloader.get_comments_from_url(url, sort_by=0) # sort_by=0: 人気順, 1: 新着順
    
    data = []
    # ここでは例として最初の10件だけ取得します
    for comment in islice(comments, 10):
        data.append({
            'Author': comment['author'],
            'Comment': comment['text'],
            'Time': comment['time'],
            'Votes': comment['votes']
        })
    
    # --- 注意点 ---
    # このライブラリはコメント取得に特化しているため、
    # タイトル取得機能は限定的です。タイトルが必要な場合、
    # 別途 `requests` + `BeautifulSoup` を組み合わせるのが一般的です。
    
    return pd.DataFrame(data)

# 実行
df_scrape = scrape_youtube_data(YOUTUBE_URL)
print(f"動画リンク: {YOUTUBE_URL}")
df_scrape.head()
```

**メリット:** APIキーが不要で、APIの制限（クォータ）を気にせずコメントを取得できる。
**デメリット:** YouTube側の仕様変更で突然動かなくなる可能性がある。取得速度はAPIより遅い。

### 1. APIを使用した場合の制限（クォータ）

YouTube Data API v3には、**1日あたり「10,000ユニット」**という無料利用枠（クォータ）が割り当てられています。
この「ユニット」はリクエスト回数そのものではなく、**APIの機能ごとに設定されたコスト**によって消費されます。

#### 主な操作の消費コスト表

| 操作 | メソッド | 消費コスト | 備考 |
| :--- | :--- | :--- | :--- |
| **動画検索** | `search.list` | **100** | キーワード検索など。**非常に高コスト**です。 |
| **動画情報取得** | `videos.list` | **1** | ID指定でタイトルや再生数を取得。 |
| **コメント取得** | `commentThreads.list` | **1** | 動画ID指定でコメントを取得。 |
| **チャンネル情報** | `channels.list` | **1** | チャンネル情報の取得。 |

#### コメント取得の限界量は？
実は、**コメント取得は非常に低コスト**です。

* コメント取得APIは、1回のリクエスト（1ユニット）で**最大100件**のコメントを取得できます。
* したがって、計算上は以下のようになります。

$$10,000 \text{ (1日の上限)} \times 100 \text{ (1回の取得数)} = \mathbf{1,000,000 \text{ 件}}$$

つまり、**動画IDが既にわかっている状態であれば、1日に最大100万件のコメントを無料で取得可能**です。
「コメントを結構取得したい」という目的であれば、APIの無料枠で十分賄える可能性が高いです。

**注意点:**
「キーワードで動画を探して（検索コスト100）、その動画のコメントを取る」という処理をループさせると、検索コストが重くのしかかり、すぐに上限に達します。**「動画IDのリスト」を事前に用意できるかどうかが鍵**です。

### 2. スクレイピングは規約上問題ないか？

結論から申し上げますと、**YouTubeの利用規約（Terms of Service）上、スクレイピングは明確に禁止されています。**

以下はYouTube利用規約「許可と制限事項」からの要約・抜粋です：

> **本サービスのいかなる部分（動画、データ等）も、自動化された手段（ロボット、ボット、スクレーパーなど）を使用してアクセス、複製、収集してはなりません。**
> （ただし、YouTubeが書面で許可した場合や、公開検索エンジンが検索インデックスを作成する場合などを除く）

#### 実情とリスク
規約上はNGですが、GitHub等には多くのYouTubeスクレイピングツールが存在し、研究や個人利用の範囲で使われているのが実情です。しかし、以下のリスクを理解しておく必要があります。

1.  **IPアドレスのブロック:**
    Colab等のサーバーから短時間に大量のアクセスを行うと、YouTube側が「攻撃」や「ボット」とみなし、そのIPからのアクセスを一時的（または永続的）に遮断することがあります（429 Too Many Requests エラー）。
2.  **法的なリスク:**
    個人利用の範囲を超えて、取得したデータを販売したり、競合サービスを作ったりする場合は、法的措置のリスクが高まります。
3.  **Colabの制限:**
    Google Colab自体も、Googleのサービスに対する過度なスクレイピング行為を検知した場合、インスタンスを停止させることがあります。

# gemini response

ご質問ありがとうございます。ここが\*\*YouTube Data APIの最大の落とし穴（コスト管理の難所）\*\*ですので、詳しく解説します。

結論から言うと、「検索」はコストが非常に高く、**1回の検索（100ユニット）で取得できるのは「最大50件」まで**です。「すべての結果」を1ユニットで見ることはできません。

また、**「検索結果（search.list）」には「再生数」や「コメント数」のデータが含まれていません。**
そのため、以下の「2段階の手順」を踏む必要があります。

### 検索からフィルタリングまでの現実的な流れ

1.  **検索する (`search.list`)**
      * キーワード（例：「作業用BGM」）で検索。
      * コスト: **100ユニット**
      * 結果: 動画IDとタイトルのリスト（最大50件）が返る。
      * *※この時点では再生数・コメント数は不明。*
2.  **詳細情報を取る (`videos.list`)**
      * 上記で得た50個のIDを使って詳細情報を取得。
      * コスト: **1ユニット**（ID指定は安いです）
      * 結果: 正確な再生数、コメント数、評価数が返る。
3.  **プログラムでフィルタリング**
      * 取得したデータに対して「コメント数〇〇件以上」等の条件で絞り込む。

-----

### 1日でどれくらい調査できるか？（計算）

1セット（動画50件分）の調査にかかるコストは **101ユニット** です。
（検索 100 + 詳細取得 1 = 101）

1日の無料枠は10,000ユニットなので：
$$10,000 \div 101 \approx 99 \text{ セット}$$
$$99 \text{ セット} \times 50 \text{ 件} = \mathbf{4,950 \text{ 件}}$$

つまり、**1日に約5,000件の動画をチェックして、その中から条件に合う動画（とコメント）を抽出する**ことが可能です。個人での分析やデータ収集としては十分な量かと思います。

-----

### 実践コード：検索 ＋ 再生数・コメント数フィルタリング

このコードは、「作業用BGM」などのキーワードで検索し、**再生数やコメント数でフィルタリングした結果**をリスト化します。

```python
from googleapiclient.discovery import build
import pandas as pd

# ★APIキーを設定
API_KEY = 'YOUR_API_KEY'

def search_and_filter_videos(keyword, max_search_count=50, min_view_count=10000, min_comment_count=100):
    youtube = build('youtube', 'v3', developerKey=API_KEY)
    
    video_data = []
    next_page_token = None
    
    print(f"検索キーワード: {keyword}")
    print("データを取得中...", end="")

    # --- 1. 検索 (search.list) ---
    # 指定された件数(max_search_count)に達するまでループ（コスト注意: 50件ごとに100ユニット消費）
    while len(video_data) < max_search_count:
        search_response = youtube.search().list(
            q=keyword,
            part='id,snippet',
            type='video',
            maxResults=50, # 1回のリクエストの上限
            order='relevance', # 関連度順 (viewCount等に変更も可能)
            pageToken=next_page_token
        ).execute()

        # 動画IDのリストを作成
        video_ids = [item['id']['videoId'] for item in search_response['items']]
        
        # --- 2. 詳細情報取得 (videos.list) ---
        # 統計情報（再生数、コメント数）を取得するために別のAPIを叩く
        stats_response = youtube.videos().list(
            part='statistics,snippet',
            id=','.join(video_ids)
        ).execute()

        # --- 3. データ抽出とフィルタリング準備 ---
        for item in stats_response['items']:
            stats = item['statistics']
            
            # コメントが無効になっている動画などは 'commentCount' がない場合があるため処理
            comment_count = int(stats.get('commentCount', 0))
            view_count = int(stats.get('viewCount', 0))
            
            # データ格納
            video_data.append({
                'Video ID': item['id'],
                'Title': item['snippet']['title'],
                'View Count': view_count,
                'Comment Count': comment_count,
                'URL': f"https://www.youtube.com/watch?v={item['id']}"
            })

        # 次のページがあるか確認
        next_page_token = search_response.get('nextPageToken')
        print(".", end="")
        if not next_page_token:
            break

    print("完了!")
    
    # DataFrameに変換
    df = pd.DataFrame(video_data)
    
    # --- 4. フィルタリング実行 ---
    # ユーザーの条件で絞り込み
    filtered_df = df[
        (df['View Count'] >= min_view_count) & 
        (df['Comment Count'] >= min_comment_count)
    ].copy()
    
    # 見やすいようにコメント数が多い順に並び替え
    filtered_df = filtered_df.sort_values(by='Comment Count', ascending=False)
    
    return filtered_df

# === 実行設定 ===
KEYWORD = "作業用BGM"
SEARCH_LIMIT = 50     # APIで調べる動画の総数（50の倍数が効率的）
MIN_VIEWS = 50000     # フィルタリング条件：再生数
MIN_COMMENTS = 50     # フィルタリング条件：コメント数

# 実行
df_result = search_and_filter_videos(KEYWORD, SEARCH_LIMIT, MIN_VIEWS, MIN_COMMENTS)

# 結果表示
print(f"\n検索対象: {SEARCH_LIMIT}件中、条件にヒットした動画: {len(df_result)}件")
df_result[['Title', 'View Count', 'Comment Count', 'URL']].head(10)
```

### コスト節約のテクニック

上記のコードの `order='relevance'`（関連度順）の部分を **`order='viewCount'`（再生数順）** に変更することをおすすめします。

  * **理由:** 「BGM」などで検索すると、再生数が少ない動画も大量にヒットします。
  * **効果:** 最初から「再生数順」でAPIからデータを貰えば、フィルタリングで生き残る（＝条件を満たす）確率が高くなり、無駄な検索コストを払わずに済みます。

このコードで「動画リストの抽出」→「フィルタリング」までは完了します。
この後、この結果（`df_result`）に含まれる `Video ID` を使って、最初の回答で紹介した「コメント取得」を行えば完璧です。

# gemini response

コメント取得に関するAPIの制限について、より技術的な仕組みも含めて具体的に整理します。

「制限がある」というのは、単に「数が取れない」という意味ではなく、**「一度にまとめて全部ドン！と取ることができないため、プログラム側で工夫が必要」**という意味合いが強いです。

具体的には以下の3つの制約があります。

---

### 1. 「1回のリクエストで最大100件」という制約（ページネーション）

これが最も大きな技術的制約です。
例えば、コメントが **10,000件** ある人気動画の全コメントを取得したいとします。

* **APIの仕様:** 「この動画のコメントを全部ください」という命令はできません。
* **実際の動き:** 「この動画のコメントを **100件だけ** ください」という命令しか受け付けません（`maxResults=100` が上限）。

**どうやって全件取るのか？**
1.  最初の100件をもらう。
2.  その時、Googleから「次の100件への引換券（`nextPageToken`）」をもらう。
3.  その引換券を使って、次の100件をもらう。
4.  また次の引換券をもらう……

これを繰り返します。つまり、10,000件のコメントを取るには、**100回のAPIリクエスト（ループ処理）** をプログラムで書く必要があります。

### 2. 「返信（リプライ）」取得の制約

YouTubeのコメントには「親コメント（トップレベル）」と、それに対する「返信（リプライ）」があります。

* **標準的な取得（`commentThreads`）:**
    親コメントを取得する際、その親に対する返信も一緒に取得できますが、**APIのレスポンスに含まれる返信は最大5件まで**という制約がある場合があります（設定によりますが、長いスレッドだと省略されることがあります）。
* **完全な取得:**
    もし、1つの親コメントに対して100件の返信がついているような激しい議論を全て取得したい場合、親コメントとは別に「その返信専用の読み込み」を追加で行う必要があります。

※ただし、通常の分析（「動画の感想を知りたい」など）であれば、親コメントとその直下の主要な返信が取れれば十分なケースがほとんどですので、そこまで複雑に考えなくて大丈夫です。

### 3. 時間（タイムラグ）の制約

上記1の「100件ずつしか取れない」ことに関連しますが、大量のコメントを取得するには時間がかかります。

* **目安:** 1回のリクエスト（100件取得）に約0.5秒〜1秒かかるとします。
* **1万件の場合:** 100回リクエスト × 1秒 ＝ **約1分40秒** かかります。
* **10万件の場合:** **約16分** かかります。

Colabで処理する場合、数千件程度なら一瞬ですが、数万件を超える動画をいくつも処理する場合は、待ち時間が発生することを考慮する必要があります。

---

### まとめ：API利用時の「制限」の正体

APIにおけるコメント取得の「制限」とは、以下の通りです。

1.  **数の上限:** 1日 **100万件** まで（無料枠としては非常に巨大。実質無制限に近い）。
2.  **取得の手間:** 一度に全件取れないため、**100件ずつループさせるプログラム**が必要。
3.  **速度:** ループさせるため、件数が多いと**取得完了までに時間がかかる**。

**結論として:**

# YouTube動画データ取得・分析ツール 要件定義書 (v1.3)

## 1. プロジェクト概要
Google Colaboratory上で動作するPythonスクリプトを作成し、YouTube Data API v3を使用して、特定のキーワードに関連する動画のメタデータおよびコメント情報を収集・リスト化する。
主な目的は、特定のジャンル（例：作業用BGM）における動画の傾向分析および視聴者の反応（コメント）の収集である。
**APIのコスト制限を考慮し、複数回に分けてデータを取得できるよう、検索の「続き」から再開できる機能を実装する。**

## 2. 開発環境・前提条件
* **プラットフォーム:** Google Colaboratory
* **言語:** Python 3.x
* **使用ライブラリ:** `google-api-python-client`, `pandas`, `glob`, `os`
* **外部連携:** YouTube Data API v3
* **保存先:** Google Drive（推奨）またはColabローカル

## 3. 機能要件

### 3.1. 動画検索・フィルタリング機能 (Phase 1)
指定されたキーワードに基づき動画を検索し、設定された閾値（再生数、コメント数）を満たす動画のみを抽出する。
**前回の検索結果の続きから開始できる機能を実装する。**

* **処理フロー:**
    1.  **パラメータ確認:** 実行時に `RESUME_PAGE_TOKEN`（再開用トークン）が指定されているか確認する。
    2.  **検索API (`search.list`)**:
        * `RESUME_PAGE_TOKEN` がある場合、それを `pageToken` パラメータにセットしてリクエストを行い、前回の続きからデータを取得する。
        * ない場合は、新規検索として最初から取得する。
    3.  **トークン保存:** APIレスポンスに含まれる **`nextPageToken`**（次のページの開始位置）を取得し、変数に保持する。
    4.  **詳細情報取得 (`videos.list`) & フィルタリング:**
        * 取得したIDリストを元に統計情報を取得し、閾値（再生数・コメント数）で絞り込む。

* **取得項目:** 動画ID、タイトル、動画URL、再生回数、コメント数、投稿日

### 3.2. コメント取得機能 (Phase 2)
Phase 1で抽出された動画リストに対し、コメントデータを取得する。
（変更なし：ページネーションを用い、`commentThreads.list` で取得）

### 3.3. データ出力機能 (Phase 3)
取得したデータと、次回の実行に必要な情報を出力する。
**同一日に複数回実行することを想定し、ファイル名には連番を付与する。**

* **ファイル命名規則:**
    * `videos_YYYYMMDD_NN.csv` (NNは01から始まる連番)
    * `comments_YYYYMMDD_NN.csv`
* **連番生成ロジック:**
    1.  保存先ディレクトリ内の既存ファイルをスキャンする（例: `videos_20260101_*.csv`）。
    2.  当日分のファイルが存在しない場合 → `_01` とする。
    3.  当日分のファイルが存在する場合 → 既存の最大番号を取得し、`+1` した番号（例: `_02`）を使用する。
* **次回用情報の表示:**
    * 処理終了時に、コンソール（標準出力）に以下のメッセージを目立つように表示する。
    * **「次回の実行時は、以下のトークンを設定してください: [取得したnextPageToken]」**
    * 可能であれば、トークンをテキストファイル（`next_token.txt`等）にも上書き保存する。

## 4. 変数・パラメータ定義（ユーザー設定項目）

| 変数名 | 説明 | 設定例 | 備考 |
| :--- | :--- | :--- | :--- |
| `API_KEY` | GCP APIキー | (必須) | |
| `SEARCH_KEYWORD` | 検索キーワード | `'作業用BGM'` | |
| `SEARCH_MAX_RESULTS` | **今回**取得したい動画の候補数 | `50` | 1回の実行で処理したい量 |
| **`RESUME_PAGE_TOKEN`** | **前回終了時のトークン** | `'CDIQAA'` | **空欄なら最初から、入力があれば続きから検索** |
| `MIN_VIEW_COUNT` | 最小再生数 | `10000` | |
| `MIN_COMMENT_COUNT` | 最小コメント数 | `50` | |

## 5. 非機能要件・制約事項

### 5.1. ページトークンによる継続処理
* YouTube Data API の `search.list` には「51件目から」という数値指定パラメータが存在しないため、必ず `pageToken` を使用して制御すること。

### 5.2. ファイル管理と連番処理（追記）
* プログラム実行時に、保存先フォルダ（カレントディレクトリまたは指定パス）を参照し、自動的に次の連番を算出すること。
* これにより、ユーザーはファイル名を意識することなく、連続してプログラムを実行可能とする。

### 5.3. エラーハンドリング
* **403 Forbidden (Quota Exceeded):** クォータ切れの場合に適切に処理を終了し、メッセージを表示すること。

# gemini response

ご質問ありがとうございます。その懸念は非常に鋭く、コスト管理において最も重要なポイントです。

結論から申し上げますと、**ご認識の通りです。**

1.  **取得本数について：** 50件取得して3件が重複だった場合、結果は **47件** になります。
2.  **コストについて：** 仮に50件すべてが重複であっても、**100ユニット（検索コスト）は消費されます。**

なぜそうなるのか、仕組みと対策を解説します。

---

### 1. なぜコストがかかるのか？（仕組み）

YouTube API側は、**「あなたが過去に何を取得したか（history.txtの中身）」を知りません。**

* **APIの仕事:** 「今の検索順位で上位50件を渡す」ことだけです。
* **プログラムの仕事:** 「貰った50件と、手元のhistory.txtを照合して、重複を捨てる」ことです。

APIからデータを受け取った時点で「検索」というサービスは完了しているため、その中身がすべて既知のデータであっても、**検索料（100ユニット）は発生**します。

### 2. 「47件」になる問題をどうするか？（要件の分岐点）

ここで、エンジニアに指示すべき**「プログラムの挙動」**を決める必要があります。2つのパターンがあります。

#### パターンA：コスト優先（推奨）
* **挙動:** 「重複を除外して47件になったら、**今回は47件でよしとして終了する**」
* **メリット:** 予期せぬコストがかからない。1回の実行＝100ユニットと計算が立つ。
* **デメリット:** 指定した50件より少なくなることがある。

#### パターンB：件数優先（いわゆる「不足分の補充」）
* **挙動:** 「3件足りないから、**もう一度APIを叩いて（追加100ユニット消費）**、次のページから3件分を補充する」
* **メリット:** 必ず50件の新しい動画が手に入る。
* **デメリット:** **コストが倍（200ユニット以上）かかるリスクがある。** もし大量に重複していると、新しい動画が見つかるまで何度も検索を繰り返し、あっという間に無料枠を食いつぶす恐れがある。

---

### 結論と要件定義への反映

今回の目的（BGM動画の収集）と、コスト制限（1日1万ユニット）を考えると、**「パターンA（コスト優先）」で実装し、重複排除の結果0件になってもエラーにしない** という安全策を取るのがベストです。

また、今回は**「ページトークン（続きから検索）」**を使う仕様にしたため、そもそも重複が発生する確率は低いです（検索順位が大幅に入れ替わらない限り、続きのページには新しい動画があるはずだからです）。

この「重複時は件数が減ることを許容する」という点を明確にするため、要件定義書の **「5.2 重複排除」** の項目を少し修正・具体化しました。

# gemini response

結論から申し上げますと、**YouTube Data API v3を使用して、チャンネルや動画が収益化されているかを直接確認することはできません。**

APIの仕様上、`monetizationStatus`（収益化ステータス）のような項目は公開されておらず、取得できるデータ（`snippet`, `statistics`, `contentDetails` 等）の中に「収益化の有無」を判定できるフラグは存在しません。

### なぜ確認できないのか？

1.  **プライバシーとビジネス情報:** 収益化の状況はクリエイターの個人の財務に関わる情報であり、Googleはこれを公開APIでは提供していません。
2.  **広告の有無 $\neq$ 収益化:** 動画に広告が表示されていても、それが「投稿者の収益」とは限りません。
    * **権利者による申し立て:** BGMなどで著作権に引っかかった場合、権利者が広告収益を受け取っていることがあります。
    * **YouTubeの権利:** 最近の規約変更により、収益化していないチャンネルの動画にもYouTube側が広告を表示するケースがあります。

---

### 代替案：エンジニアに依頼できる「推測」ロジック

APIで直接「収益化しているか」は分かりませんが、**「収益化の条件を満たしている可能性が高いチャンネル」**を抽出することは可能です。

YouTubeパートナープログラム（収益化）の最低条件は以下の通りです。
* **チャンネル登録者数:** 1,000人以上
* （その他、総再生時間などの条件はありますが、APIでは取得不可）

したがって、要件定義書には「収益化チェック」の代わりに、**「登録者数によるフィルタリング」**を追加するのが最も現実的な解決策です。

### 要件定義書への反映 (v1.5)

これまでの議論を踏まえ、以下の変更を行いました。
1.  **「収益化チェック」は不可能なので除外。**
2.  **代わりに「チャンネル登録者数（Subscriber Count）」を取得し、フィルタリング条件に追加。**
    * これにより、「登録者1000人未満（＝絶対に収益化していないチャンネル）」を除外できます。

> * **収益化判定について:** APIでは正確な収益化ステータスが取得できないため、代替策として `subscriberCount`（登録者数）によるフィルタリングを採用しています。
> * **実装のヒント:** `videos.list` の結果に含まれる `channelId` を集めて、`channels.list(id=..., part='statistics')` を叩くことで登録者数が取得できます。ここも50件ずつまとめてリクエストしてください。
