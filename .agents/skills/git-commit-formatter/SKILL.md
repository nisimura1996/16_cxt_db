# Git Commit Formatter Skill (コミットメッセージ整形技術)

Gitのコミットメッセージを書く際は、必ず **Conventional Commits** 仕様に従う必要があります。

## フォーマット
`<type>[optional scope]: <description>`
（タイプ[任意のスコープ]: 日本語の概要）

## 許可されているタイプ
- **feat**: 新機能の追加
- **fix**: バグ修正
- **docs**: ドキュメントのみの変更
- **style**: コードの意味に影響を与えない変更（ホワイトスペース、フォーマット、セミコロンの欠落など）
- **refactor**: バグ修正や機能追加ではないコードの変更
- **perf**: パフォーマンスを向上させるコードの変更
- **test**: 不足しているテストの追加や既存のテストの修正
- **chore**: ビルドプロセスや補助ツールの変更、ライブラリの更新など

## 指示
1. 変更内容を分析し、主要な「タイプ」を決定してください。
2. 該当する場合、スコープ（特定のコンポーネントやファイル名）を特定してください。
3. **重要**: 概要（description）は必ず**日本語**で記述してください。
4. 破壊的変更（Breaking Changes）がある場合は、フッターの最初に `BREAKING CHANGE:` を追加してください。
5. **実行確認**:
   ユーザーに実行の許可を求める際は、必ず「**'y' (Yes) または 'n' (No)**」で回答するように案内してください。（例: 「この内容でコミットしてよろしいですか？ 'y' または 'n' で回答してください」）

## 例
`feat(auth): Googleログイン機能を実装`
